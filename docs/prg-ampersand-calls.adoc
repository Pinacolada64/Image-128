=== `&` Routines

`&` is the command character which is BASIC`'s interface to the machine language routines of Image BBS.
Image BBS 3.0 has 70 of them, `&,1` to `&,70`; Image BBS 128 has the same 70 with the same numbers, and two of its own, <<amp-71,`&,71`>> and <<amp-72,`&,72`>> (the jump table is `asm/jmptb.asm`).

[[amp-128-differences]]
.What's different on the 128
****
* An `&` routine's registers come back in `peek(6)`, `peek(7)` and `peek(8)` (`+{sym:sareg}+`, `+{sym:sxreg}+`, `+{sym:syreg}+`), not the C64's 780-782.
So `&,4`, `&,20,_x_,1`, `&,23` and `&,48` leave their result in `peek(6)`.
* Most of Image's memory locations moved.
This chapter gives the 128's, as names from `asm/equates.asm` with the number after: in a `.lbl` listing, write the name, `+poke {sym:mask},42+`, and the build puts the number in (see <<pokes>>).
* `&,16` and `&,17` run the overlay at `protostart`, `$1c00` (7168), not 49152.
* New sub-functions of `&,15`: <<center,`&,15,7`>> centers a string, <<widest,`&,15,8`>> measures the widest of `tt$()`, <<using,`&,15,9`>> catches BASIC 7.0's `print using` in a string.
* `&,13` is the Lt. Kernal lock, working since 11/12/2026: <<arbit>>.
* The 128 screen editor's Esc sequences work in `&` output on the console: <<writing-amp-output>>.
* Source files are `+asm/*.asm+` in the Image BBS 128 repository where 3.0's guide names `+source/*.s+`; `modules/i.test calls.lbl` is the test program, with each call at the same line as 3.0's (<<trying-the-amp-calls>>).
****

==== `&`: Image BBS Output

In BASIC, the `print` keyword (or its abbreviation, `?`) displays text on the screen.
For example:

[source,imagebasic]
----
print"Hello there!"
----

or

[source,imagebasic]
----
?"Hello there!"
----

both produce the text:

----
Hello there!
----

You can substitute `&` in Image BBS to do the same thing:

[source,imagebasic]
& "Hello there!"

But unlike BASIC, after outputting this text, the cursor remains on the same line--there is no automatic carriage return printed.

It`'s as if a semicolon (`;`) was used after the `print` statement above--this keeps the text all on one line:

[source,imagebasic]
print"Hello ";"there!"

Gives the result:

 Hello there!

vs. printing on two lines:

[source,imagebasic]
print"Hello"
print"there!"

Gives the result:

====
 Hello
 there
====

To work around this, you can output a _carriage return_, which moves the cursor to the beginning of the next line.

.Details: CR/LF, CR, LF?
****
On other terminals or operating systems, a carriage return moves the cursor to the beginning of the current line.

Sometimes an additional _linefeed_ character is needed, which keeps the cursor in the current column, but moves the cursor down a row.

 Hello
       there!

This stairstep-looking result is what printing looks like with only a linefeed, when the terminal needed both a carriage return and a linefeed.
Probably not the desired result.

However, ``print``ing in Commodore BASIC--and our BBS in this example--doesn`'t need a linefeed.
A carriage return is the equivalent of a carriage return plus linefeed.
****

[source,imagebasic]
&"Hello there!"+chr$(13)

`chr$()` (read it as "`character string`") is a function that outputs a character supplied in parentheses.
A carriage return is `chr$(13)`.
So this snippet of code will output `Hello there!`, then move the cursor to the beginning of the next line.

There is also a string variable defined in `im`: `r$=chr$(13)` (short for "`return`").
This is a handy shortcut.
You can now code:

[source,imagebasic]
&"Hello there!"+r$

==== Encoded Function Keys [[encoded-function-keys]]

Some special characters are difficult (or impossible) to type in BASIC.
Or, they might cause problems while reading disk files.
Therefore, they have been encoded using the reverse video letters seen while typing function keys when in Commodore`'s "`quote mode.`"

This eliminates a few difficulties:

* Entering special characters is made easier--instead of `chr$()` codes, you can just tap a function key in quote mode

* Some more simply written code (and BASIC itself) can truncate data when a `,` is encountered in a SEQ file--this character encoding eliminates that problem

Image BBS converts these special characters from their encoded form to readable characters when you:

* use kbd:[RD] to read a SEQ file
* use kbd:[SB] to read a post
* Use kbd:[WF] to kbd:[.G]et, kbd:[.E]dit, and kbd:[.P]ut a file back.

The `image seq reader` utility used in BASIC also does this.

TIP: <<_15_4,`&,15,4`>> does the same thing to `an$`, the string to translate.
<<_15_2,`&,15,2`>> is similar, but leaves kbd:[f5], kbd:[f6] and kbd:[f8] encoded, since those would break a record in a SEQ file.

As it relates to carriage returns, though, we can see in the following table:

.Image BBS Encoded Function Keys

===== Typed Input Is Encoded [[input-encoding]]

Image BBS also encodes characters as they are typed.
Its input routines, such as <<amp-1-input-line,`&,1`>> (line input) and <<_23_get_character_from_modem,`&,23` Get Character from Modem>> (get a character), replace each typed `,` `:` `"` `*` `?` `=` and `^` with its encoded character.
kbd:[Return] is left alone, since it ends the input.

This means:

* What a user types can be written to a SEQ file as it is: commas, colons and quotes can't break up the record.
* A program checking what was typed must compare against the encoded character.
A typed `?` arrives as `chr$(137)`, so `if an$="?" then...` is never true; use `if an$=chr$(137) then...`.
* Wildcards typed for `&,60,11` Scan for String (in 3.0's Structures chapter, not ported yet) arrive ready to use.

There is no `&` call to encode a string built in BASIC; `&,15,2`, <<_15_4,`&,15,4` Decode All Function Keys>> and <<convstr,`&,64` Convert String>> only decode.
Write the encoded characters in yourself, _e.g._ `"ok"+chr$(136)`.

The encoding is done by `getchr` in `asm/chrio.asm`, from `getchr11` on: each character is looked up in the ML's `spchars` table (`$0e0b`, in the buffer page), and if found (except kbd:[Return]), replaced with `$85` plus its position in the table.

==== Writing `&` output

* After THEN, write `+then:&"..."+`: the wedge only sees `&` at the start
of a statement, so `+then &"..."+` is a `?syntax error`.
* With `lp=1` before it, a string is printed with word wrap, and the ML
ends the line itself unless the string ends with a space; `lp` is back
to 0 after each string, so set it before each one (<<_word_wrap>>).
* The 128 screen editor's Esc sequences work in `&` output (11/05/2026),
in 40 and 80 columns: Esc goes to the editor's own print (`$c72d`), and
so does the character after it, so the editor runs the sequence on the
cursor Image uses. Write the Esc as `+{$1b}+` in the string (or
`chr$(27)` in `a$`). Clearing:
** `+&"{$1b}q"+` clears from the cursor to the end of its line;
** `+&"{$1b}@"+` clears from the cursor to the end of the window: the
editor's window, whose bottom Image keeps at `botline` (row 23, or 15
with the screen mask on: `setwin`), so the mask's rows stay.
+
Put the cursor first with `&,70,column,row`. `im` 3414 clears under the
boot frame this way (`+&,70,0,6:&"{$1b}@"+`). Only on the console: a
caller's terminal doesn't know the 128's Esc codes, so leave them out
of text that callers see. `tests/standin/escq.bas` and `escq80.bas`
try both.

=== BASIC Editing Modes

==== Quote Mode
In the BASIC editor, once the quote mark (kbd:[Shift+2], kbd:["]) is typed, color or cursor controls stop changing the cursor color or moving the cursor.
Instead, they start displaying reversed characters which stand for the color control, cursor control or symbol you are typing.
Once the text inside the quotes is ``print``ed, they perform their functions as if typed manually.
The kbd:[Inst/Del] key is the only cursor control not affected by "`quote mode.`"

Typing a second kbd:["] exits quote mode, and allows you to use the cursor keys to edit the program line again.

====
TIP: See <<position-cursor>> for how to easily move the terminal cursor within Image BBS, instead of using lots of cursor controls in quote mode.
====

==== Insert Mode
Insert mode is similar to quote mode, only for the number of spaces you insert with the kbd:[Shift+Inst/Del] key, the BASIC editor is in quote mode.
Once the space inserted has been typed in, insert mode is exited.

****
TIP: kbd:[Return] gets out of quote and insert mode, and adds the current line into the BASIC program.
kbd:[Shift+Return] gets out of quote and insert mode, but does _not_ add the current line into the BASIC program.
****

==== Word-Wrap

// source: foldoc.org

A new feature of the text output routine is _word-wrap_.
This is where a word which would extend past the right hand margin is moved to the following line instead.

The position to wrap words is usually 40 columns on the console, whatever the remote user`'s screen width is, and 80 columns on the printer, if one is attached.

Setting the variable `lp=1` and outputting text with `&"..."` will enable word-wrap.

[source,imagebasic]
t=50:lp=1:&"Generating {pound}!t unique random numbers..."

outputs:

 Generating 50 unique random numbers...

Setting `lp=0` disables word-wrap, so words continue past the right margin.

NOTE: With `lp=1`, `&` ends its output with a carriage return of its own, unless the last character was a space, and then sets `lp` back to `0` (`asm/strio.asm`, `outstr3`).
So don't end a word-wrapped line with `\{f6}` as well: it would be followed by a blank line.
Set `lp=1` again before each `&` that should wrap.

==== Set Margins

The left and right margins can now be indented by up to 15 characters using two new MCI commands:

// source: s.menu 3

* `&#163;m<__x__` (set left margin).
This command causes every carriage return issued by Image BBS to be followed by _x_ spaces, which indents text _x_ spaces.
The values for _x_ are `0` (to disable word-wrap), or `1-9`, and `j-o` (10-15).

* `&#163;m>__x__` (set right margin).
This command causes the system to word wrap as if the user`'s screen width was _x_ characters less than it really is.
It indents the text from the right side.

The use of `&#163;m<__x__` and `&#163;m>__x__` together allows you to make "`block indents`" of text that appear correct regardless of the user`'s screen width.

=== Outputting Numbers

==== Floating Point

_Floating point_ values are not integers--the value could be fractional, and the decimal point could be in any position, hence the term "`floating point.`"

`&str$(h)`::
Since `&h` isn`'t supported to output the value of `h`, it must be converted to a string with the `str$()` function.

TIP: `&str$(h)` is still useful if the number of digits output is greater than 5, the limit of the MCI numeric output routine.

`&str$(h)` worked under Image 1.2; it works here too, but there is a new MCI command in Image 3.0 to output single-letter floating point variables:

`&"£!h"`::
Output the value of `h`.

TIP: You cannot specify the number of digits or leading characters to output as with integer variables.
Unlike BASIC's `print`, no leading space is printed before a positive number or zero, so your `&` statement must allow for that.

To output a two-character variable name (_e.g._, `xx`, `c1`), you have some choices:

* assign the two-character variable name to a single letter variable name, _e.g._:

[source,imagebasic]
xx=500:x=xx:&"Blocks free: £!x"

Output `Blocks free: 500`.

* output the two-character variable using the `str$()` function, which _will_ output a leading space if the value is positive or zero, or a leading `-` if the value is negative:

[source,imagebasic]
xx=100:&"Number of days:"+str$(xx)

Output ``Number of days: 100``.

[source,imagebasic]
xx=-3.14:&"Value of pi in the mirror universe:"+str$(xx)

Output `Value of pi in the mirror universe:-3.14`

TIP: On the 128, BASIC 7.0's `print using` formats a number (digits, commas, decimal places, a `$`) and <<using,`&,15,9`>> catches what it prints in a string for `&`: `+&,15,9:print using "##,###.##";x;:&,15,9,1:&"You owe $"+a$+".{f6}"+`.

== ``&`` Parameters Explained

`&` commands from this point on have additional parameter(s) called by at least one number, followed by optional parameter(s).
These variables are denoted in _italics_.

`&,_call_`::
This means that `&,` is required, but the value of _call_ varies.
Substitute the appropriate number in its place.

.Example

<<_40_forcegc,`&,40` forcegc>>: perform garbage collection

`&,_call[,optional]_`::
This means that, again, `&,_call_` is required.
The value of _call_ varies.
However, the parameter _[,optional]_ is not required.
If it is supplied, there needs to be a `,` and the appropriate parameter substituted in its place.

.Example

<<amp-9-bottom-variable,`&,9,1` Bottom Variable>>: display `a$` in the 16-character programmable window

// &,_call_[,_optional_[,_parameter_]] -- don't think this ever happens

There are various sections which most commands use.
They outline BASIC setup (variables or ``poke``s) which need to be done before the `&` call can be used.

_Enter:_ ::
Any ``poke``s or BASIC variables which are used by the ``&`` command are listed here.

_Parameters:_ ::
Any extra information given after `&,_x_`, like strings or numbers, are listed here.

_Exit:_ ::
Strings, numbers or arrays returned when the `&` command is finished are listed here.

_Examples:_ ::
Examples of setup, the `&` call being used, and some typical results are listed here.

=== `&,1` Input Line [[amp-1-input-line]]

`&,1` accepts input from the user at a prompt.
It handles features including word wrap, MCI access, line length, and the ability to type graphics characters.

_Enter:_

`poke 53252,_line_length_` limits the length of the input to _line_length_ characters, 1-79.
53252 (`llen`, `$d004`) is the same address on the 128 as on the C64: in a `.lbl` listing, `+poke {sym:llen},n+` for a length of _n_.

`p$`: text of the prompt shown before `:&#160;` and input is accepted.

`w$`: the default response to a prompt.
When using edit mode, if only kbd:[Return] is typed at a prompt, `an$` is set to a null string (`an$=""`).
The module can check for this and not update the original string.
An example is given below.

// from &,1 documentation

`pl=0`: allow both lowercase and uppercase.

`pl=1`: convert lowercase input to uppercase.

NOTE: Typed `,` `:` `"` `*` `?` `=` and `^` arrive in `an$` already encoded, _e.g._ a typed `?` is `chr$(137)`.
See <<input-encoding>>.

_Parameters:_

`&,1,_editor_[,_password_]`

`editor` and `password` are the `&` call's _x_ and _y_ values: the input routine (`inline`, in `asm/swap1.asm`) gets them in the X and Y registers.

`editor`: editor flags:

Each bit controls a separate function of the input routine.
Bits may be combined to perform multiple functions.

.Input Line: Editor Control Bits

[%autowidth]
[cols=">1m,>2m,<3"]

|=====
| Binary | Decimal | Purpose (if set)

| %00000010 | 2 | kbd:[.] or kbd:[/] on column one exits input

| %00000100 | 4 | don't show the prompt (`p$`)

| %00001000 | 8 | allow typing kbd:[&#163;] (the MCI command character)

| %00010000 | 16 | enable word-wrap

| %00100000 | 32 | enable edit mode

| %01000000 | 64 | ignore time remaining (input isn't cut off when time runs out)

| %10000000 | 128 | kbd:[Delete] on column one exits input

_Exit:_

[%header]

[%autowidth]
|===
| Variable | Purpose
| an$
| a copy of the text the user typed.
If the user did not type anything and just hit kbd:[Return] or kbd:[Enter], `an$` is set to a null string (`""`).

`peek(53254)` (`chat`, `$d006`, the same on the 128) returns status information:

[%header]
[%autowidth]
[cols="1m,2", frame="none", grid="rows"]
|===
| Value | Purpose
| 0 | normal exit

| 1 | kbd:[Delete], kbd:[.] or kbd:[/] typed on column 1

| 2 | Left `Cht` checkmark (enter chat mode) on lightbar was activated by sysop

//* 0 = normal *
//* 1 = delete on column one *
//* or dot on column one *
//* 2 = chat check hit *
//* 3 = carrier/time loss *

_Explanations:_

Test program: `modules/i.test calls.lbl`, line `{:3250}`: password input, masked and not shown, and input with any editor flags, which you turn on and off one at a time from a list.

Edit mode::
The prompt (`p$`) is displayed, and the default response (`w$`) is displayed.
Then, the prompt (`p$`) is displayed again, and one of three choices can be made:

* kbd:[Return] accepts the default (`w$`)
* a new string can be typed
* the current string can be edited using kbd:[Ctrl] key shortcuts

`password`: password flags:

.Input Line: Password Entry Control Bits
[%header]
[%autowidth]
|=====
| Binary | Decimal | Purpose
| `%00000001` | 1 | show the mask character, `+peek({sym:mask})+` (2786, `$0ae2`; 4850 on the C64; `X` when Image starts), for each character typed
| `%00000010` | 2 | no output: nothing typed is shown
|=====

`an$` holds what was actually typed either way.

NOTE: `&,1` clears the password flags when input ends (`inline`, `asm/swap1.asm`), as <<_6_password_input,`&,6` Password Input>> does.
Image 3.0's, before October 2026, left them set, so after `&,1,_x_,1` everything Image printed came out as the mask character until the next `&,1`.

_Exit:_

`an$`: text typed at the prompt.

_Examples:_

.Input Line: Password, Masked
[source,imagebasic]
poke 53252,15:p$="Password":&,1,0,1

`&,1,0,1`: no editor flags; password flag 1 shows the mask character (`X` unless changed with `+poke {sym:mask},c+`, _c_ a character code) for each character typed.

.Input Line: Password, Not Shown
[source,imagebasic]
poke 53252,15:p$="Password":&,1,0,2

`&,1,0,2`: password flag 2 shows nothing as the user types.

.Input Line: Set Line Length and Prompt
[source,imagebasic]
poke 53252,10:p$="Name":&,1

`poke 53252,10`: Set the input length to 10 characters.

`p$="Name"`: Set the prompt to `Name:`.

`&,1`: Allow user input, and return string in `an$`.

.Input Line: Set Line Length, Default Text, Prompt and Edit Mode
[source,imagebasic]
poke 53252,20:w$=na$:p$="Handle":&,1,32:if an$<>"" then na$=an$

`poke 53252,20`: Set the input length to 20 characters.

`w$=na$`: Assign the user`'s handle (`na$`) to `w$` (the prompt`'s default).

`p$="Handle"`: Set the prompt to `Handle:`.

`&,1,32`: Setting bit 5 (a value of 32) enables edit mode.
This displays the prompt, the original text (`w$`), and re-displays the prompt.
Editing control keys can be used to change the input.
Editing mode looks like this:

 Handle: PINACOLADA
 Handle: _

The string typed in response to a prompt is returned in `an$`.

`if an$<>"" then na$=an$`: Just typing kbd:[Return] (to accept the default, `w$`) sets `an$` to a null string.
If something else was typed (`an$<>""`), assign `na$` to what was typed (`an$`).

.Input Line: Set Line Length, Default Text, Prompt and Allow MCI & Graphics Characters
[source,imagebasic]
poke 53252,30:p$="New Prompt":&,1,9:if an$<>"" then po$=an$

`poke 53252,30`: Set the input length to 30 characters.

`p$="New Prompt"`: Set the prompt to `New Prompt:`.

`&,1,9`: Setting bits 3 and 0 (a value of 8 + 1) allow MCI and graphics characters to be entered.

=== `&,2` Disk File Input

Input data from an open disk file.
This routine inputs a maximum of 80 characters into `a$`.

_Parameters:_

`&,2,_lfn[,bytes]_`

`lfn`: logical file number.

====
.Logical File Numbers
// source: C64 Programmer's Reference Guide, modified
A logical file number (LFN) relates the `open`, `close`, `cmd`, `get#`, `input#` and `print#` statements to each other.

LFNs help distinguish multiple files from each other.
They associate the commands being used with the filename opened which uses the same LFN.

The LFN is the first number in an `open` statement, _e.g._ `open **2**,10,2`.

////
This and can be a useful debugging tool.
If you have an input file open on LFN #1, and an output file open on LFN #2, #FIXME#
////

The LFN value ranges from 1 to 255.
LFN 15 is usually reserved for the DOS command channel.

The only restriction is that you can't re-`open` a LFN that is already `open`, or you get the error `?file open&#160;&#160;error`.
====

`bytes`: number of bytes to get from file (1-80).
Carriage returns are ignored.

_Exit:_

`a$`: bytes from file

NOTE: On the 128, `a$` is made a string of its own as the call ends (`dskina`, `asm/miscl.asm`).
BASIC 7.0 copies only a string's pointer in `x$=a$`, so without this every copy of `a$` (`im`'s `d3$`, ``sub.modem``'s `mt$`...) changed with the next line read.
An ML caller (an overlay through `usetbl1`) gets the bytes in Image's buffer, as on the C64.

_Example:_

.s.test file
----
data <1>
----+----+----+----+----+----+ <2>
----

<1> a regular string

<2> a 30-character string (with `+` every 5 characters to simplify keeping track of string position), used to demonstrate `&,2,2,25`

.i.read test file
[source,imagebasic]
3000 dr=1:a$="s.test file,s,r":gosub 4 <1>
3002 if e% then:&:goto 3100 <2>
3004 &,2,2:& <3>
3006 &,2,2,25:& <4>
3100 close 2:goto 300 <5>

<1> `dr=1`: set the Image drive to `1` (the System drive).

=== `&,13` arbit: locks between Lt. Kernal stations [[arbit]]

On a multiplexed Lt. Kernal hard drive, the stations (up to 16 computers,
the host adapter's ports 0-15) share one drive, and two writing the same
file at once can wreck it. `&,13` is Image's lock between them (`arbit`,
`asm/miscl.asm`, from Image 2.0; the 128's since 11/12/2026):

[width="100%",cols="50%,50%",options="header",]
|===
|Call |Does
|`&,13,1,n` |takes lock `n` (0-15), waiting while another station has it (a reverse `L` on the status line meanwhile); taken twice, it must be given back twice
|`&,13,2,n` |gives it back
|===

Take the lock, do the writes, give it back. Without a Lt. Kernal (or its
`lockfile`) both do nothing, so a module can call them on any system.

A lock is only a number the stations agree on: it doesn't know about
files, and a station that writes without taking it isn't stopped. Pick one
lock for each file (or set of files written together) that more than one
station writes, and have every module that writes it take that lock.

[width="100%",cols="34%,33%,33%",options="header",]
|===
|Lock |Used by |For
|0 |`pass:c[++ chatmode]` |the transcript in `chatfile` (only the room's writer takes it)
|1-15 | |free
|===

From BASIC, around writes to a shared file:

[source,imagebasic]
----
3100 &,13,1,1:dr=3:a$="e.idle 1,s,a":gosub 4:print#2,d1$","b$:close 2:&,13,2,1
----

From ML (as `pass:c[++ chatmode]` does): `+ldx #1+` (take; `+#2+` give back),
`+ldy #lock+`, `+lda #13+`, `jsr usetbl1`.

* *It waits as long as it takes.* There's no time limit and no way out:
the station shows a reverse `L` at column 31 of the status line (row 24,
copied to the VDC in 80 columns too) until the lock is free, and the
caller sees nothing happen. So hold a lock only for the writes
themselves: never across a prompt, a key, or a modem transfer.
* *Taking it again is fine:* a station that holds a lock gets it again
at once, and the count goes up; it's free once the count is back to 0
(as many gives as takes). Giving back a lock the station doesn't hold
does nothing, and so does a lock past 15 or any call but 1 and 2.
* *A station that crashes holding a lock* keeps it until it boots
again: `lockinit` frees that station's locks then (the owner is the
port). Until it does, the others wait on that lock. There's no command
to free it from another station yet.
* *The lockfile:* `lockfile` on LU 10, user 0, 17 contiguous blocks:
its header, then a block for each lock: the owner (its port + `$80`; 0
for none) and how many times it has taken it. `lockinit` (intro.asm, at
``im``'s `sys 7171`) finds it, or makes it (2.0 only found it), and frees
every lock in a new one, and in any case the locks this station held
before a crash or a reset.
* *Taking one:* read its block; free (or already this station's): write
this station's and the count, wait (up to ~65 ms, CIA 1's timer B), read
it again, and start over if another station wrote in between.
* *On the 128:* the Lt. Kernal's routines (BNKOUT, BNKIN, DRIVER) are
in its own ROM and RAM, where Image's ML can't call them from its
configuration, so the block reads and writes are in glue.asm
(`ltkblock`, `ltklkblk`, the shared 16K), with `$ff00` set as W. J.
Brier's LK Mini-Mon (a C-128 program) sets it. The Lt. Kernal is found
as the C64 found it, by the `jsr` its KERNAL has at `$ffd2` (read with
the ROMs in), once, at boot.

`tests/standin/lock.bas` (`+tools/ltk_lock.py+`) tries it on two x128s
sharing VICE's emulated Lt. Kernal.

===== Image BBS Date Format [[date-format]]

Image BBS uses an 11-digit string to represent a time and date.
The format is `w&#160;yr&#160;mo&#160;dt&#160;hr&#160;mi`.

====
NOTE: Extra spaces between the numbers have been added for ease of reading, but are not used in the actual string.
====

////
1  90 11 03 80 45    IMAGE BBS will translate this into the string
^  ^  ^  ^  ^  ^     "Sun, Nov  3 1990  12:45 PM"
|  |  |  |  |  |
|  |  |  |  |  +---- Minute   00-59
|  |  |  |  |
|  |  |  |  +------- Hour     00-11: AM
|  |  |  |                    80-91: PM (subtract 80 to get correct hour)
|  |  |  |
|  |  |  +---------- Date     01-31
|  |  |
|  |  +------------- Month    01-12
|  |
|  +---------------- Year     00-99     (plus hard-coded century base)
|
+------------------- Weekday   1-7      (1=Sunday...7=Saturday)
////

.Image BBS Date Format
[%autowidth]
[%header]
[cols="<,^,<,<"]
|===
| Position | Abbreviation | Purpose | Range
| 1     | `**&#160;w**` | weekday | `1`=Sun...`7`=Sat
| 2-3   | `**yr**` | year    | `00`...`99` (the year within the century, `20xx`, is displayed using `&,15`)
| 4-5   | `**mo**` | month   | `01`...`12`
| 6-7   | `**dt**` | date    | `01`...`31`
| 8-9   | `**hr**` | hour    | `12`, `01`...`11` (12:00 AM, midnight--11:00 AM, 1 hour until noon)

`92`, `81`...`91` (12:00 PM, noon--11:00 PM, 1 hour until midnight)

`00` and `80` are also accepted as 12 AM and 12 PM (see note below)
| 10-11 ^| `**mi**` | minute  | `00`...`59`
|===

====
NOTE: The hour is the CIA #1 time-of-day clock's hours register, written as two BCD digits.
Bit 7 of that register is the PM flag, which is why PM hours start at `8`.
The clock counts `12`, `01`...`11` for AM hours, so midnight is `12` and noon is `92`; it never shows `00` or `80`.

When converting a date to text, `&,15` and kbd:[Ctrl+d] accept either `12`/`00` for 12 AM and `92`/`80` for 12 PM.
<<newdate,`&,15,5`>> changes `12` to `00` and `92` to `80` so that dates sort correctly.

The 12 o`'clock hour is shown as `12` and `92` in the source: see `irq2` (the midnight check `hrs = $12`), `makdate` (`asm/irqhn.asm`), and `htom`/`mtoh` (`asm/swap3.asm`).
The 128 uses the same clock, CIA #1's.
====

The current time and date is stored in the string `d1$`, which is continually updated by the ML.
Here is a sample definition of `d1$`:

 "22105178944"

Let's break down how the string is encoded.

.Image BBS Date Decoding
[%autowidth]
[%header]
[cols="<,^,<,<"]
|===
| Position | Value | Purpose | Meaning
| 1     | `&#160;2` | weekday | `Mon`
| 2-3   | `21` | year    | `2021`
| 4-5   | `05` | month   | `May`
| 6-7   | `17` | date    | `17`
| 8-9   | `89` | hour    | `&#160;9:00 PM` (`9`=hour, plus `80`=PM)
| 10-11 | `44` | minute  | `44`
|===

As the table above shows, this string stands for `Mon May 17, 2021&#160;&#160;9:44 PM`.

====
NOTE: You can also output kbd:[Ctrl+d] or `chr$(4)` in an `&` statement to convert an 11-digit date/time string to a long date/time string.
Both these statements output the same string as above:

* `a$="22105178944":&"` kbd:[Ctrl+D] `"+a$` (in a C64List listing, kbd:[Ctrl+D] is written `{$04}`)

==== `&,15,5` newdate [[newdate]]

=== `&,24` xchrout1 [[xchrout1]]

:function_count: 1
include::includes/prg-ml-function-warning.adoc[]

Output one character to the user, through Image BBS's output routine: to the local screen, the modem and the printer, in the current output mode.
This is the routine to use when writing ML that needs to output a character.

_Enter:_

`$fe` (254): the character to output.
`xchrout1` doesn't take the character from the accumulator.

_Exit:_

The X and Y registers are preserved; the accumulator holds the character (from `$fe`).

==== Calling It

* In the main ML (`asm/chrio.asm`), `xchrout` stores the accumulator in `$fe` and falls through into `xchrout1`.
* An ML module (`++` file) calls it by number, through the interface page at `$192a` (`usetbl1`, 6442; `$cd03` on the C64), as `asm/struct.asm` and `asm/visual.asm` do:
+
[source,asm]
----
xchrout:
		sta $fe		// the character
xchrout1:
		lda #24		// &,24
		jmp usetbl1	// $192a (c64: $cd03): run & call 24
----
+
`usetbl1` also saves A, X and Y in `sareg`, `sxreg` and `syreg` (6-8; 780-782 on the C64) for the call.
On the 128 it goes through `farcall`, so an overlay started with `sys` can call it too.
`asm/swap1.asm` has a variant, `xchrout0`, which outputs nothing at all when the password "`no output`" mode is on (`passmode` bit 1).

* From BASIC, `&"`...`"` is the usual way to output text.
A single character could be sent with ``poke 254,``__c__``:&,24``, though this hasn't been tested; `poke 254,c:&,51` sends one to the modem alone (<<outmod>>).

==== What It Does

`xchrout1` saves X and Y and calls `outchr` (`asm/chrio.asm`), which:

. turns the encoded input characters `$85`-`$8c` back into what was typed (`,` `:` `"` `*` `?` `=` `^`: see <<input-encoding>>), with `chkspcl` (`$1936`; `$cd0f` on the C64);
. picks the output mode (`setoutmd`), checked again for every character:
+
[%autowidth]
[%header]
|===
| When | Output

| Password mask on (`passmode` bit 0, `$0aea`)
| Control codes are sent as they are; any other character is replaced by the mask character (`mask`, `$0ae2`), as when a password is typed.

| Bit 7 of `mci` (`$18d7`, 6350) set: "`show control codes`" (see below)
| Control codes (except kbd:[Return] and kbd:[Delete]) are shown instead of acted on: as the character plus 64, in reverse, so `{white}` (5) shows as a reverse `E`.

| Word wrap on (`wrapflg`, 6266)
| Characters are collected in `wrapbuf` (6186, up to 80) until a space or control code ends the word.
If the word won't fit on the screen, printer or modem line, a kbd:[Return] goes first; then the word is sent.

| Otherwise
| The character goes to the screen (`outscn0`), the modem (`outmdm0`) and the printer (`outptr`).
|===

==== `mci` (6350)

On the C64, `mci` is 2031 (`$07ef`); on the 128, `+{sym:mci}+`, 6350 (`$18d7`).


`mci` controls MCI and control codes in output:

* bit 0 set: MCI commands aren't interpreted (Image BBS 1.2's `poke 2031,1`; on the 128, `+poke {sym:mci},1+`);
* bit 7 set: control codes are shown, as above.

The message editor sets `mci` to `$81` (both) for its `.L` List, `.R` Read, `.E` Edit, `.F` Find and `.K` Replace commands, so the text appears exactly as stored, with its codes visible; and to `0` for `.M` MCI Read, which shows the text as it will look (`asm/editor.asm`, `comlist`).
The source doesn't name bit 7: "`show control codes`" is a description.

The visual editor (`asm/visual.asm`) outputs everything through its own `xchrout`, which also keeps track of where this leaves the caller's cursor (see <<position-cursor>>).

=== `&,26` Find Record by Flags and Name [[ecschk]]

Search a table of fixed-size records held in an integer array (such as a struct: see <<_60_structures,`&,60`>>) for the first record whose flag word shares a bit with _mask_, and whose name matches _string$_.

The routine is called `ecschk` in the source, but it is not the same as the `ecschk` used by <<_42_check_for_ecs_command,`&,42`>>.

====
NOTE: This description comes from reading the source code (see <<ecschk-source>>), and has not been tested on a running BBS yet.
Nothing in Image BBS 3.0's BASIC code calls `&,26`, and nothing in the 128's does.
====

.Syntax
`&,26,` _size_, _count_, _mask_, _array%(element)_, _string$_

.Parameters
[%autowidth]
[%header]
|===
| Parameter | Range | Purpose

| _size_
| `0`-`255`
| Length of each record, in bytes

| _count_
| `0`-`255`
| Number of records to search (`0` searches 256 records)

| _mask_
| `0`-`65535`
| Bits to test against each record's flag word.
A negative number gives `?illegal quantity&#160;&#160;error`.

| _array%(element)_
|
| The array element where the first record starts

| _string$_
|
| The name to search for: a string variable or a literal string.
Only the first 8 characters are used.
|===

.Exit
`a%`: the number of the first matching record, counting from `1`; `0` if no record matches.

==== Record Layout

Each record is _size_ bytes long.
`&,26` only looks at bytes 2-3 and 6-13; the other bytes can hold anything.

.&,26 Record Layout
[%autowidth]
[%header]
|===
| Bytes | In an integer array | Purpose

| 0-1
| _element_
| Not used by `&,26`

| 2-3
| _element_+1
| Flag word: byte 2 is ``and``ed with the high byte of _mask_, byte 3 with the low byte

| 4-5
| _element_+2
| Not used by `&,26`

| 6-13
| _element_+3 to +6
| Name: 8 bytes, padded with `chr$(0)` (as stored by `&,60,0` Put String)
|===

A record matches when both of these are true:

. _Flag test_: the flag word and _mask_ have at least one bit in common.
. _Name test_: the record's name bytes equal _string$_, padded with `chr$(0)` to 8 characters.
If _size_ is less than 14, only the name bytes up to the end of the record are compared.

==== Special Cases

[%autowidth]
[%header]
|===
| Condition | Result

| _string$_ is empty (`""`)
| `a%=0` without searching

| _mask_ is `0`
| `a%=0`: no flag word can share a bit with `0`

| _count_ is `0`
| 256 records are searched

| The match is past record 255
| Can't be returned: the record number is only 1 byte

| The flag word has bit 15 set
| The flag word is stored as a negative number in the array (_e.g._ `-32768`), but the bit is passed in _mask_ as a positive number (`32768`)
|===

==== Example

Structs store each record's fields next to each other, so in `t%(7,2)` each record `t%(0-7,_r_)` is 8 integers, or 16 bytes long.

[source,imagebasic]
dim t%(7,2)
t%(1,1)=1:&,60,0,8,t%(3,1),"FOO"
t%(1,2)=2:&,60,0,8,t%(3,2),"BAR"
&,26,16,2,2,t%(0,1),"BAR":&"{pound}%a"

.Result
`2`: record 2 is the first record with bit `2` set in its flag word and the name `BAR`.

==== Possible Use [[ecschk-possible-use]]

====
NOTE: This section is an interpretation, based on how similar code elsewhere in Image BBS works.
It has not been confirmed by any code that calls `&,26`.
====

`&,26` answers the question: "`Is the command this user typed in my command table, and are they allowed to use it?`"

Think of the table as a list of commands.
Each record holds:

* the command's name (_e.g._ `FOO` or `BAR`), and
* a flag word saying which access groups may use it: one bit per group.

You pass in what the user typed as _string$_, and a _mask_ with the user's own access group bit set.
If the command is in the table _and_ the user's bit is set in its flag word, `a%` returns its record number; otherwise, `0`.
The program can then branch on that number, with `on a% goto...` or <<calcgoto,`&,66` Calculated `goto`>>.

===== Why the Mask Is Probably a "`Who\'s Allowed`" Bit

The ECS (Extended Command Set) module used by <<_42_check_for_ecs_command,`&,42`>> does almost the same job, and its code shows what the mask is for.
It builds a mask with one bit set for the user's access level, `ac%`, by shifting a `1` bit left `ac%` times:

[source,asm]
ldx #var_ac_integer  ; ac% = user's access level
...
sec                  ; the 1 bit to shift in
lda #0
sta acc
sta acc+1
ecsc3:
rol acc              ; acc = 2^ac%
rol acc+1
dex
bpl ecsc3

It then ``and``s that bit with each command's access bytes, and compares the command name: the same pattern as `&,26`.
The difference is that `&,26` lets the caller choose the mask, the record size and where the table is, while <<_42_ecs_commands,`&,42` ECS Commands>> uses its own fixed ECS table format.

===== Example: An Access-Checked Command Lookup

[source,imagebasic]
' ct%(7,n): command table; name in ct%(3,r), allowed access groups in ct%(1,r)
' nc: number of commands; cm$: command the user typed
' a level 5 user has mask 2^5=32
' int(...+.5): C64 BASIC's ^ can return a value slightly below a whole number
m=int(2^ac%+.5):&,26,16,nc,m,ct%(0,1),cm$
if a%=0 then &"Unknown command.{f6}":return
on a% goto 1000,1100,1200

This does in one machine language call what would otherwise be a slow BASIC loop comparing strings.

===== Why Nothing Calls It

`&,26` may be left over from an earlier way of handling ECS, where command definitions were held in a BASIC struct and searched with `&,26`.
When Image BBS 3.0 moved ECS into its own swapped-in module (`&,42`, with its own table format), `&,26` stayed in the jump table, but nothing used it any more.
This would also explain why the routine is named `ecschk`.

#TODO#: Check Image BBS 2.0's ECS code to confirm or rule this out.

`&,26` could still be useful for any "`find by name, but only if allowed`" table, such as a sysop's own commands, file transfer protocols, or sub-boards limited to certain access groups.

=== `&,27` Save Variable Pointers [[save-variable-pointers]]

This saves pointers that tell BASIC where variables and arrays start and end.
When modules introduce arrays not already defined in `im`, the variable pointers can be restored with `&,28`.
This erases unnecessary variables after they're done being used.

`&,27[,_level_]` saves where BASIC's arrays start and end as a numbered level (left out, 0; only _level_ `and 7` counts).
<<restore-variable-pointers,`&,28[,_level_]`>> puts them back, which drops every simple variable and array made since: a module ``dim``s its arrays after an `&,27` and gets their memory back with the `&,28`.
The routines are Image 3.0's (`arraysv0`, `asm/wedge.asm`; `&,28` is `asm/arrays.asm`), at the same addresses.

A level is two numbers, not a copy of the arrays: `arytab`-`vartab` and `strend`-`vartab`, 4 bytes at `$13d0`+4×_level_ (`arryptrs`, bank 0).
They are offsets, not addresses, so a level still fits when a module of another length loads and the variables move.

* *Levels 4-6 write over `daysofm`* (`$13e0`-`$13eb`, the days in each month, used by the time zone date change): only `$13d0`-`$13df` is set aside (`arryptrs`, 16 bytes, levels 0-3).
Level 7 lands on `emptym2`, 4 spare bytes.
Image uses 0 (`im` 304), 1 (boot; the main prompt and the error trap restore it), 2 (`i/MM.load`), 3 (the idle screen, `i/IM.modem`) and 7 (`sub.menus`): use 2 and 3 in modules.
* Make every simple variable you still need after the `&,28` before the `&,27`: one first used in between is dropped (using it again makes a new one, `0` or `""`).
* A level hides nothing: BASIC finds an array anywhere from `arytab` to `strend`.
So `&,27,3:dim tt$(10):&,27,4:dim tt$(10)` does _not_ give two `tt$()` arrays: the second `dim` is `?redim'd array`.
(And in `im`, `tt$()` is already ``dim``ensioned: any `dim tt$()` is that error.)
* Levels nest: `&,27,3`, ``dim``s, `&,27,4`, ``dim``s; `&,28,4` drops the second set, `&,28,3` the first.

==== Creating New Arrays

If you define any new arrays in a module, be sure not to consume unnecessary memory after you end the module.
You can do this by using the `&,27` (array pointer save) and <<restore-variable-pointers,`&,28` Restore Variable Pointers>> (array pointer restore) calls.

====
Image 1.2 had just one level of variable pointer save and restore.
Image 1.3 and above adds multiple levels of save and restore with an additional parameter.
// Reflections: 2.0 Facts vs. Fiction
====

.Save and Restore Variable Pointers
[source]
----
3000 &,27,2 <1>
3002 dim u%(10,20) <2>
...
3010 &,28,2:goto 300 <3>
----
<1> save current variable pointers, and create variable pointer level 2

<2> create new array

<3> <<restore-variable-pointers,`&,28,2` Restore Variable Pointers>>: restore level 2 array pointers (this frees up memory used by the array but preserves level 1 system variables still needed by the BBS). `goto 300`: go to main prompt.

===	`&,58` setalarm [[set-alarm]]

Set the alarm time on Complex Interface Adapter #1 (CIA #1).

_Parameters:_

`&,58,_hour_,_minute_`

`hour`: hour, in the same form as <<set-time,`&,62` Set Time>> uses (_e.g._ `81` for 1 PM)

`minute`: minute

`&,58` shares its code with <<set-time,`&,62` Set Time>> (`setalm` and `settim` in `asm/irqhn.asm`).
The differences are that `&,58` writes to the CIA's alarm registers instead of the clock, and does _not_ swap hours `12` and `92` (see <<set-time>>).
A BASIC program has to do that swap itself.

_Example:_

.im 3182: set the clock, then the alarm
[source,imagebasic]
&,62,b,c:b=b+80*((b=92)-(b=12))+12*((b=93)or(b=13)):&,58,b,.

After setting the clock to ``b``:``c``, this swaps hours `12` and `92` in `b`, then sets the alarm to ``b``:``00``.

The expression also changes `13` to `1` and `93` to `81`, though neither can come from `d1$`.
This suggests the alarm was meant to be set to the top of the _next_ hour (`b+1`).
As written, the alarm is set to the current hour at `:00`, which has already passed.

In Image BBS 3.0 and 128, the CIA alarm doesn't trigger anything:

* `setirq` (`asm/intro.asm`) writes `$1f` to CIA #1's interrupt control register (`$dc0d`).
With bit 7 clear, this turns _off_ all five CIA #1 interrupt sources, the alarm included: Image BBS runs from the VIC-II raster interrupt instead (on the 128, ahead of the KERNAL's own handler).
* Nothing checks the alarm's flag in `$dc0d` either.
The only other code that reads `$dc0d` is `tdelay` (`asm/miscl.asm`), which waits for Timer B, and clears all the flags as it reads them.

So `&,58` is probably left over from an earlier version, which would also explain why setting the alarm to an hour that has already passed went unnoticed.

NOTE: The lightbar's alarms (Alarm Triggers, in 3.0's lightbar appendix, not ported yet) don't use the CIA alarm.
They are a table of 16 entries at `alarmtb` (`$1660`, 8 bytes each: see `asm/equates.asm`), loaded at boot.
Once a minute, after updating the date, the IRQ handler calls `alarm` (`asm/irqhn.asm`), which works out the minute of the day (`cminute`, also copied to `mn%`) and, for each enabled entry, sets its lightbar check mark at its "`set`" minute and clears it at its "`clear`" minute.
The NetMail alarm times (`netalrm`) are checked the same way, and set the `Net` right check mark.

=== `&,62` Set Time [[set-time]]

Set the hours and minutes of the BBS clock: the time-of-day (TOD) clock in Complex Interface Adapter #1 (CIA #1).
The date is not changed.
The 128 has the same CIA #1 and the same code (`settim`, `asm/irqhn.asm`).

====
NOTE: This description comes from reading the source code (see <<set-time-source>>), and has not been tested on a running BBS yet.
====

.Syntax
`&,62,` _hour_, _minute_

.Parameters
[%autowidth]
[%header]
|===
| Parameter | Range | Purpose

| _hour_
| see below
| Hour, in the same form as `d1$` (see the <<date-format>>)

| _minute_
| `0`-`59`
| Minute
|===

Both values are converted to BCD (binary coded decimal) and written to the CIA's hours and minutes registers.
Bit 7 of the hours register is the PM flag, so `80`-`92` (`$80`-`$92` in BCD) are PM hours:

.&,62 Hour Values
[%autowidth]
[%header]
|===
| _hour_ | CIA hours register | Time

| `12`
| `$12`
| 12 AM (midnight hour)

| `1`-`11`
| `$01`-`$11`
| 1 AM-11 AM

| `92`
| `$92`
| 12 PM (noon hour)

| `81`-`91`
| `$81`-`$91`
| 1 PM-11 PM
|===

`0` and `80` are not valid hours for the CIA clock, and are not checked for.
It is not yet known what the CIA does with them.

==== Why Hours 12 and 92 Are Swapped

The 6526 CIA flips the AM/PM flag whenever hour 12 is written to its hours register.
To make up for this, `&,62` writes `$92` when it is asked for 12 AM (which the CIA flips to `$12`), and `$12` when it is asked for 12 PM (which the CIA flips to `$92`).

<<set-alarm,`&,58`>> (Set Alarm) uses the same code, but does _not_ do this swap.

==== Side Effects

* Seconds and tenths of a second are set to `0`.
Writing tenths last also restarts the clock: the CIA stops updating its time-of-day registers after the hours register is written, until tenths is written.
* CIA #1 control register B (`$dc0f`) is set to `$01`: time-of-day writes set the clock (not the alarm), timer B is started, and the register's other bits are cleared.
* The next IRQ updates the clock on the screen, as if a minute had passed.
If a user is online with 1-100 minutes left, this also takes 1 minute off their time remaining.

==== Example

.im 3170-3182: set the date and time from z$
[source,imagebasic]
----
3170 a=val(left$(z$,1)):gosub 3184:poke {sym:bootdate_at},a
3172 a=val(mid$(z$,2,2)):gosub 3184:poke {sym:bootdate_at}+3,a
3174 a=val(mid$(z$,4,2)):gosub 3184:poke {sym:bootdate_at}+1,a
3176 a=val(mid$(z$,6,2)):gosub 3184:poke {sym:bootdate_at}+2,a
3178 b=val(mid$(z$,8,2))
3180 c=val(mid$(z$,10,2))
3182 &,62,b,c:b=b+80*((b=92)-(b=12))+12*((b=93)or(b=13)):&,58,b,.:return
----

`z$` holds an 11-digit date.
`&,62` only sets the time, so the weekday, year, month and date are converted to BCD (by 3184) and ``poke``d into the ML's date storage (`bootdate`, `asm/buffer-page.asm`, at `bootdate_at`: `$0ec7`; `$cec7` on the C64) instead.
`sub.clocks` does the same when it sets the BBS's clock from a clock source.

=== `&,70` Position Terminal Cursor [[position-cursor]]

Move the cursor to a column and row, on both the local screen and the caller's terminal.

_Parameters_:

`&,70,_column_,_row_`

[%autowidth]

|===

=== `&,71` putvar2

:function_count: 1

New on the 128.
Stores the 5 bytes at `var` (`$63`) in the variable or array element whose descriptor `varpnt` (`$49`/`$4a` on the 128; `$47`/`$48` on the C64) points to, as <<_30_putvar,`&,30` putvar>> does once it has found the variable (`putvar2`, `asm/varbl.asm`).

New on the 128.

[width="100%",cols="50%,50%",options="header",]
|===
|Call |Does
